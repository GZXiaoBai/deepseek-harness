# Agent Note: 应用内审查台（开发者面板）

Status: implemented
Archived: 2026-08-20

[English](2026-08-18-dev-panel.md) | 中文

## 问题

Web UI 没有侧边审查面：details 栏只展示被选中的工具调用，会话审查只能靠聊天内的 Trajectory tab，待办交互在 composer 里应答。用户在 agent 回合进行中没有应用内的位置来浏览工作区、扫视会话或查看 git 状态。社区插件（`dsh-side-panel`）覆盖了部分需求，但它是外部 bundle，有自己的文件/git 通道且默认不出现。

## 决策

标准 web profile 内置官方审查面板，默认开启，由一个 details 栏 tab 加一个侧栏底部触发器组成：

- `ui-conversation` 把 details 栏改造成 tab 容器：现有工具调用面板成为 **工具详情** tab，新声明的子槽 `conversation.details.devpanel` 承载审查面板。选中工具调用时自动切到工具 tab；手动点击的 tab 保持。tab 栏是 conversation 拥有的 chrome；标签耦合只有一对语言键。
- `@deepseek-ai/dsh-host-dev-panel` 提供四个只读回环路由（`/dev-panel.list-files`、`.read-file`、`.git-status`、`.git-diff`）。每个路径都解析在客户端提供的 workspace 根之内（`confineToWorkspace` 拒绝绝对路径、`..` 逃逸与越界符号链接）；文件读取为 UTF-8 且限制 512 KiB；git 经 `ctx.shell` 执行器运行（只读动词），因此部署的沙箱与策略同样生效。
- `@deepseek-ai/dsh-client-ui-dev-panel` 把底部触发器注册进此前无人使用的 `sidebar.footer.action` list 槽（`ctx.layout.openDetails()`），把面板本体注册进 `conversation.details.devpanel`。面板的 workspace 根与会话行来自 session 标准套件；历史行目前仅展示。

面板是纯展示：从不触达模型请求，也不产生会话事件。

## 曾考虑的替代方案

**采用 `dsh-side-panel`。** 社区 bundle 现在就能装，但它未签名也未审查，路由没有 loopback 限定的 workspace 围栏，而且要在标准 profile 默认出现终究要打进 bundle。

**第四列布局。** details 栏已存在，tab 栏比新的几何所有者改动更小；独立一列会重复 concession/宽度机制。

**完整写权限（建文件、暂存 git）。** 审查是 v1 契约；写入属于 agent 工具及其权限流程。

## 结果

标准 profile 现在有审查面，带机械的包含性边界（host 单元测试）与 shell 策略 git。历史跳转消息与二进制预览推迟（记录在包 README）。桌面运行时闭包需要在桌面分支合并本改动时把两个新包加入 `apps/desktop/runtime/package.json`。
