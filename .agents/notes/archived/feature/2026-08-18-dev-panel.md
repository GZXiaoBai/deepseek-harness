# Agent Note: In-app review panel (dev panel)

Status: implemented
Archived: 2026-08-20

English | [中文](2026-08-18-dev-panel.zh.md)

## Problem

The Web UI had no side review surface: the details column showed only the selected tool call, conversation review lived inside the chat as the Trajectory tab, and pending interactions were answered in the composer. Users had no in-app place to browse the workspace, scan the conversation, or inspect git state while an agent turn ran. A community plugin (`dsh-side-panel`) covered part of the need, but as an external bundle with its own file/git channels and no default presence.

## Decision

The standard web profile ships an official review panel, default-on, composed as one details-column tab plus one sidebar footer trigger:

- `ui-conversation` owns the details column as a tabbed container: the existing tool-call panel becomes the **Tool Details** tab, and a new declared child slot `conversation.details.devpanel` hosts the review panel. A selected tool call auto-selects the tool tab; manual tab clicks stick. The tab bar is conversation-owned chrome; the label coupling is one locale key pair.
- `@deepseek-ai/dsh-host-dev-panel` serves four read-only loopback routes (`/dev-panel.list-files`, `.read-file`, `.git-status`, `.git-diff`). Every path resolves inside the client-supplied workspace root (`confineToWorkspace` rejects absolute paths, `..` escapes, and escaping symlinks); file reads are UTF-8 and bounded at 512 KiB; git runs through the `ctx.shell` executor (read-only verbs), so the deployment's sandbox and policy apply.
- `@deepseek-ai/dsh-client-ui-dev-panel` registers the footer trigger into the previously empty `sidebar.footer.action` list slot (`ctx.layout.openDetails()`) and the panel body into `conversation.details.devpanel`. The panel derives its workspace root and conversation rows from the session standard kit; history rows are display-only for now.

The panel is pure presentation: it never reaches a model request and emits no session events.

## Alternatives considered

**Adopt `dsh-side-panel`.** The community bundle is installable today, but it is not signed or reviewed, its routes are not loopback-confined to the workspace, and default-on presence in the standard profile requires shipping it in the bundle anyway.

**A fourth layout column.** The details column already exists and its tab bar is a smaller change than a new geometry owner; a separate column would duplicate the concession/width machinery.

**Full write access (create files, stage git).** Reviewing is the v1 contract; writes belong to the agent tools and their permission flow.

## Consequences

The standard profile now has a review surface with a mechanical containment boundary (host unit tests) and shell-policy git. History jump-to-message and binary previews are deferred (documented in the package README). The desktop runtime closure needs the two new packages added to `apps/desktop/runtime/package.json` when the desktop branch merges this change.
